# 01 · 아키텍처 — 왜 하이브리드인가

## 두 도구, 두 본성

**cmux**는 사람이 보는 화면입니다. 여러 페인(pane)에 Claude Code 세션을 나란히 띄우고, 원격 제어(Remote Control)로 폰에서도 master와 대화할 수 있습니다. 페인 구조·크기·재시작 바인딩을 기억해 앱 재실행 시 세션까지 복원합니다.

**cys**는 함대 도구입니다. 역할(role) 기반으로 에이전트 노드를 스폰하고, 노드 목록·컨텍스트 사용량 관측·인박스 채널을 제공합니다.

한쪽만으로도 운영은 됩니다. 그러나 실운영에서 갈라지는 지점이 있습니다.

- 사람이 **항상 지켜보는 세션**(master·CSO)은 화면에 상주해야 하고, 재부팅 후에도 같은 자리에서 살아나야 합니다 → cmux 페인.
- **티켓 단위로 생겼다 사라지는 워커**는 화면 배치보다 역할 관리·일괄 관측이 중요합니다 → cys 노드.

그래서 결론은 하이브리드입니다: **지휘는 cmux, 실행은 cys.**

## 역할 설계

```
오너(사람) ─ 최종 권한. 비가역 결정·외부 발행·비용 결정의 게이트.
└─ master ─ 단일 통제점. 오너 채널 유일 보유(원격 제어 1기만).
     ├─ CSO ─ 시스템 감시(부하·컨텍스트·발화 검증). 경량 센티널 상시 + 지능 온디맨드.
     └─ 워커 N ─ 티켓 실행. 완료·질문·막힘은 master에게 push.
```

세 가지 불변 규칙이 이 구조를 지킵니다.

1. **서열 불변** — 오너 > master > 보조 관리자 > 워커. 보조 관리자는 위임 영역만 감독하고 master를 우회할 수 없습니다. 충돌·교착은 master로 즉시 이관.
2. **채널 단일화** — 오너의 폰에 노출되는 세션은 master 단 1기입니다. 워커가 각자 오너에게 말을 걸기 시작하면 통제가 무너집니다.
3. **master의 원격 채널은 항상 ON** — 꺼진 것을 인지하면 오너에게 "켜 달라"고 안내하는 것이 아니라 **스스로 복구**합니다. 오너가 외출 중이면 그 안내 자체가 전달되지 않는 데드락이기 때문입니다.

## 주소 체계 — 가장 많이 다치는 곳

멀티 페인 운영에서 가장 흔한 사고는 **엉뚱한 페인에 명령을 보내는 것**입니다. 우리가 확정한 원칙:

> **표시명은 사람 것, 주소는 기계 것 — 섞지 않는다.**

- **페인 번호는 정체성이 아닙니다.** 재부팅마다 번호가 뒤집힙니다(실증: master=1·CSO=2였다가 재부팅 후 정반대). 자기 페인은 환경변수(`$CMUX_SURFACE_ID`), 남의 페인은 라이브 해석 스크립트로 찾습니다.
- **탭 제목도 주소가 아닙니다.** Claude Code가 작업 내용에 따라 제목을 자동 변경하므로, 제목을 1차 키로 쓰면 아무도 손대지 않았는데 배선이 끊깁니다(실사고). 역할→페인 해석의 권위는 **cwd(작업 디렉터리)**입니다. `scripts/jarvis-who.sh`가 이 원칙의 구현입니다.
- cys 노드는 애초에 `role=` 필드로 찾습니다(`scripts/cys-who.sh`).
- 페인 제목은 사람(오너)의 것입니다. 오너가 아무 이름으로 바꿔도 배선이 깨지지 않아야 합니다. 다만 기동 시 초기 제목은 「번호 + 역할 한 단어」로 지어 오너가 화면과 대조할 수 있게 합니다.

## 상주 페인 구성 (예시)

우리 구성은 좌→우로: **master(약 20%) · lead · worker-1 · worker-2 · worker-3 · cso** — 오너는 master만 봅니다. master 가시성이 최우선이고, 나머지는 균등 분할입니다. 페인 수·역할은 자기 규모에 맞게 줄이세요. 최소 구성은 master + 워커 1 + (선택) CSO입니다.

## 워커의 두 얼굴: 페인 워커와 cys 노드

- **상주 페인 워커** — 정기 작업(일일 스캔 등)이나 긴 프로젝트 전담. cmux 페인에 상주.
- **cys 노드 워커** — 티켓 단위 스폰·완주·폐역. `scripts/spawn-worker.sh`가 단일 입구입니다(모델 지정·역할 부여·각성 주입·페인 제목까지 한 동작). 입구를 하나로 강제하는 이유는 8번 문서(규율 증류)에서 다룹니다: **경로를 둘로 두면 매번 고르는 단계가 남고, 그 고르는 단계가 곧 사고의 자리가 된다.**

## 왜 "전면 이사"가 아닌가

cys만으로 전부 통일하는 안도, cmux만으로 버티는 안도 검토했고 기각했습니다. 지휘 세션(사람이 보는 것)과 실행 노드(도구가 관리하는 것)는 요구 조건이 다르며, 억지로 한쪽에 맞추면 다른 쪽의 강점(cmux의 복원·원격 제어 / cys의 역할 관측·함대 관리)을 잃습니다. 하이브리드의 비용은 "주소 체계 이원화"인데, 이는 위의 who-스크립트 계층으로 흡수 가능합니다.
