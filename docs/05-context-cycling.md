# 05 · 컨텍스트 순환 — 측정과 예측 기반 순환

상주 세션(master·CSO)은 컨텍스트가 차오르는 것과의 싸움입니다. 이 문서는 두 가지를 다룹니다: **어떻게 재는가**, **언제 순환(갈무리 후 /clear)하는가**.

## 측정 — 출처 없는 숫자를 말하지 않는다

자기 세션의 컨텍스트 사용량 정본은 **세션 JSONL 파일 실측**입니다:

```
마지막 usage 레코드의 (input + cache_creation + cache_read + output) ÷ 모델 컨텍스트 창
```

규칙 세 개:

1. **CTX 숫자에는 언제나 출처+시점을 붙입니다**: `30.9%(jsonl 라이브·09:16)`. 출처 없이 CTX를 말하지 않습니다.
2. **파일은 반드시 라이브인 쪽을 고릅니다.** 같은 세션 id가 복수 경로에 있으면 mtime 최신을 고르고 후보 수를 명시합니다. 실사고: 폴더 이사가 만든 죽은 복제본을 감시기가 읽어 29%를 16%로 과소보고했습니다. **판정 로직이 맞아도 입력이 오염되면 오판입니다.**
3. **분모는 모델마다 다릅니다.** 모델 미확인 상태의 % 인용을 금지합니다(자동 강등으로 모델이 바뀌어 있을 수 있습니다 — 복원 체크리스트에 모델 실측이 들어가는 이유).

워커의 CTX는 함대 도구의 관측값을 쓰되, **신선도(관측 시각) 병기 없는 인용을 금지**합니다.

## 순환 규칙 — 밴드가 아니라 예측

처음에는 "45~60% 밴드에 들면 다음 자연 경계에서 순환"으로 운영했습니다. 결과: 이틀 연속 45%대의 **바닥 순환** — 복원 고정비만 내고 맥락을 버렸습니다. 그래서 예측 기반으로 교체했습니다.

1. **50% = 관측 전환** — 증가율(%p/10분) 측정을 시작합니다. 행동은 없습니다.
2. **순환 시점 = 예측 기반** — 「대기 작업을 얹었을 때 70%를 넘길 것으로 예측되는 지점의 **마지막 여유 자연 경계**(티켓 종결·발주 직후·문답 일단락)」에서 순환합니다. 예측 = 최근 증가율 × 대기 작업 크기.
3. **60% 이후 새 대형 작업 개시 금지.**
4. **70% = 소프트 상한**(진행 중 매듭 완결만 허용) · **75%+ = 사고로 계수**(잘린 트랜잭션·유실 계보 — 원인 분석 의무).
5. **긴 공백 예상(취침·외출) 시 30%+면 선제 갈무리·순환.** 프롬프트 캐시 만료 후 첫 턴은 프리픽스 전체를 재과금하므로, 공백 전 순환이 임계값보다 토큰 효율을 지배합니다.

워커는 별도로 단순하게: **티켓 수명 = 세션 수명, 60% = 정지선.**

## 순환 스냅샷 — 재무장 체크리스트

순환 직전 SOT에 남기는 스냅샷은 서사가 아니라 **체크리스트**입니다. 우리 실물 서식:

```
## 🔄 [날짜 시각 · 순환 스냅샷] 사유(CTX %·출처·예측 근거)
- 재무장 체크: ①원격 채널 상태 ②인박스 Monitor(태스크 id) ③cron 목록(각 id)
  ④모델 확인 ⑤함대 현황(역할·상태) ⑥절전 방지 프로세스 ⑦인박스 스윕 기점 = NNNN줄
- 완결 총괄: (이번 세션에서 끝난 것들 — 한 줄씩)
- 대기: (다음 세션이 이어받을 것 — 해소 판정법 포함)
- 주의 이월: (함정·날짜 예약·감시 포인트)
```

핵심은 **⑦ 인박스 스윕 기점**입니다. 다음 세션의 갭 스윕이 이 줄번호에서 시작합니다(3번 문서). 이 숫자가 없으면 "어디까지 처리했는지"가 기억에만 있게 되고, 기억은 순환과 함께 지워집니다.

## 갈무리의 목적

세션 transcript는 디스크에 상시 기록되므로 종료 방식과 무관하게 남습니다. **갈무리(SOT 갱신)의 목적은 "종료 대비"가 아니라 "/clear·새 세션 대비"입니다.** 다음 세션이 transcript 전체를 다시 읽는 것은 불가능하므로, 사람이 읽을 수 있는 압축본(SOT)이 인수인계 문서가 됩니다.

## 상주 노드의 무손실 재시작

모델 변경·기동 설정 갱신이 필요할 때 세션을 버릴 필요가 없습니다: Ctrl+C 두 번 → 셸 → `claude --continue`. `--continue`가 그 cwd의 최신 대화를 자동으로 이어줍니다. 잃는 것은 진행 중이던 도구 실행뿐입니다.

⚠ 앱의 재시작 바인딩이 옛 세션 id에 고착되는 함정이 있습니다. `--resume <고정 id>`로 묶어 두면 앱 재시작 시 며칠 전 컨텍스트로 부활합니다(실사고). 바인딩은 `--continue`(cwd 기반 최신 자동)로 걸어 구조적으로 고착을 없앱니다.
