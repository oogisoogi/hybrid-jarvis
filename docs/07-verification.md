# 07 · 검증 — 환각 0·적대검증·초록불의 함정

에이전트 함대의 산출물 품질은 검증 구조가 결정합니다. 이 문서는 우리가 실사고로 값을 치르고 확정한 검증 규율입니다.

## 환각 0 — 4문

모든 단정에 네 가지를 요구합니다: **출처 진실성 · 근거 적합성 · 논리 오류 · 팩트체크.** 과장·거짓 확신 금지. 확신도를 표시하고, "내가 못 찾았다"와 "존재하지 않는다"를 구분합니다(과소 인용도 오인용입니다 — 접근 경로를 명시하고, "없다"고 말하기 전에 원장·코드·대화 세 곳을 봅니다).

## 위험비례 적대검증

모든 작업에 같은 강도의 검증을 걸면 비용이 무너지고, 중요 작업에 약한 검증을 걸면 품질이 무너집니다. 위험 등급에 비례시킵니다:

- **경량(저위험)**: 워커 자체검증 + master 스팟 체크.
- **중요(L2+)**: **이종 검증 의무** — 다른 모델 계열에게 "반박하라"(REFUTE)로 시킵니다. 같은 모델의 재검토는 같은 맹점을 공유합니다.
- **고위험(비가역·저신뢰·이종 미수행)**: 오너 게이트 잔존.
- 수렴 판정은 "서로 다른 검증자가 연속으로 새 결함 0"일 때. 잔여 불확실성은 행적으로 보고합니다(무엇을 검증 안 했는지 정직하게).

역할 분리 원칙: **만든 자가 평가하지 않는다(producer ≠ evaluator).** 구현 워커, 이종 검증자, 최종 판정자(master)를 나눕니다. 외부 LLM의 판정만으로 수렴 선언은 불가 — 최종 판정은 지휘 세션이 자기 실측으로 합니다.

## 초록불의 함정 — 테스트가 대상을 안 만났다

가장 값비싼 교훈: **초록불이 "대상을 한 번도 안 만난 검사"일 수 있습니다.**

- grep 0건도 초록불입니다 — 패턴이 실물과 안 맞으면 "없음"이 나오고, "없음"은 조용히 맞아 보입니다(감시 프로세스가 11시간째 살아 있는데 좁힌 패턴으로 "부재" 판정한 실사고).
- 검증 환경이 발행 환경과 다르면, 파일 단독 렌더는 통과하고 발행본은 깨집니다(발행 채널이 콘텐츠를 포장하면 검증도 포장된 상태로 해야 합니다 — 라이브에서만 글자가 14px로 추락한 실사고).
- 한 번도 발화한 적 없는 경보 경로는 미검증 코드입니다. **강제 발화**로 실제로 울리는지 확인합니다.

### 처방: 뮤테이션 검산 (음성 대조)

테스트가 대상을 정말 물고 있는지 확인하는 가장 싼 방법: **일부러 결함을 주입하고 테스트가 빨간불이 되는지 봅니다.** 게이트 제거 → 정확히 예상한 검사만 적색 → 원복 후 green. 양성만 본 검사는 아무것도 증명하지 않습니다 — "Yes"만 보고 판별기라 부르지 마세요.

## 측정 입력부터 검증

판정 로직이 맞아도 입력이 오염되면 오판입니다. 관측값을 쓰기 전에:

- 도구 2종 교차(한 계기의 값이 수상하면 다른 계기로 대조)
- 라이브/스테일 구분(같은 이름의 죽은 복제본·낡은 스크롤백을 읽고 있지 않은지)
- **같은 이름의 옵션이 백엔드마다 반대 뜻일 수 있습니다.** "명령을 안다"와 "그 백엔드에서 그 옵션이 무슨 뜻인지 안다"는 다릅니다(같은 `--lines` 옵션이 한 도구에선 라이브 화면, 다른 도구에선 과거 스크롤백이었던 실사고 — 9시간 전 화면을 라이브로 읽었습니다).

## 계수 보고에는 축을 명시

"신청 1건"이라는 실측이 유령 사건을 만든 적이 있습니다 — 한 계측은 테스트 계정 포함, 다른 계측은 제외였고, 그 차이가 "첫 실신청"이라는 허구를 제조해 이후 세션들에 사실로 전파됐습니다. **실측이 있어도 축이 다르면 유령을 만듭니다.** 계수는 "전체 몇·그중 테스트 몇·실데이터 몇"으로 축을 병기하고, 관측 숫자에는 범위를 병기합니다("이상 0"은 범위 없으면 정보가 아닙니다).

## 최상급 주장은 값 대조를 통과해야

"가장 크다·최신이다·유일하다" 같은 최상급 주장은 값이 실존해도 서열이 틀릴 수 있습니다. 지적된 곳만 고치지 말고 전수 대조하고, 동률은 규칙으로 처리합니다.

## 문서를 읽은 것 ≠ 실제 상태를 확인한 것

하루에 같은 오류를 세 번 낸 적이 있습니다: 소스 코드만 읽고 동작 단정 / 기본 브랜치만 보고 최신 단정 / 문서만 읽고 설정 단정. 설치본에 직접 묻는 명령 한 줄이면 즉시 드러났습니다. **판정 전에 실물에 물어보세요.** 그리고 방어책에는 만료 검토를 함께 적으세요 — 근본 원인이 사라져도 체크리스트는 계속 돌며, 이미 해결된 문제를 열흘간 방어하게 됩니다("무엇을 보면 해소를 알 수 있는가"를 백로그에 함께 적는 이유).
