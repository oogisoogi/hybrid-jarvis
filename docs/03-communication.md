# 03 · 통신 — 발신 원장·인박스·고스트 판별

멀티 세션 운영의 두 번째 사고 다발 지역은 통신입니다. 페인 간 메시지는 셸을 두 번 통과하고(보내는 쪽·받는 쪽), 파일 채널은 폴링이며, 누가 보냈는지 증명할 방법이 기본으로는 없습니다. 이 문서는 그 세 문제의 처방입니다.

## 1. 발신 — 단일 입구 래퍼

master의 모든 페인 발신은 래퍼 하나(`scripts/master-send.sh`)로 나갑니다. 래퍼가 한 동작으로 처리하는 것:

**입력줄 비움 확인 → 전송 → 도달 실측 → Enter(제출) → 제출 판정 → 원장 기록**

### 본문은 언제나 인용 heredoc으로

```bash
master-send.sh <surface-ref> - <<'EOF'
<본문 — 백틱·$·따옴표 무엇이든 그대로 나간다>
EOF
```

⛔ 인라인 인자로 본문을 넘기지 마세요. 큰따옴표 안의 **백틱은 셸 명령치환**이라, 코드 인용이 **빈 문자열로 사라진 채 발송**됩니다. 받는 쪽은 문장이 멀쩡해 보여 훼손을 모릅니다(하루 4회 실사고 후 박제). `<<'EOF'`(따옴표 친 구분자)는 셸 확장 단계 자체가 없어 원문이 그대로 갑니다.

⛔ "짧으면 인라인" 예외도 두지 마세요. **경로를 둘로 두면 매 발신마다 "어느 쪽을 쓸까" 고르는 단계가 남고, 그 고르는 단계가 곧 기억이며, 기억은 실패합니다.** 같은 사고를 래퍼 사용자는 4번, 처음부터 heredoc만 쓴 사용자는 0번 냈습니다. 차이는 주의력이 아니라 경로였습니다.

### 전송 후 반드시 Enter

크로스 페인 전송은 「본문 send → 약 2초 대기 → Enter(send-key Return)」가 한 세트입니다. Enter 없이는 입력줄에 얹힐 뿐 제출되지 않습니다. 래퍼가 이것을 자동화하지만, 폴백으로 생 send를 쓸 때는 손으로 지켜야 합니다.

## 2. 원장 — 발신의 증명

래퍼는 발신마다 본문에 **1회용 표식**(`[master#<6hex>]`)을 자동으로 붙이고, append-only 원장(JSONL)에 기록합니다. 효과:

- **표식 없음 = 우회 또는 위조**가 성립합니다.
- 수신자는 원장 조회로 "정말 master가 보낸 것인지"를 검증할 수 있습니다.

### 고스트(위조 지시) 판별 규칙 — 세 개의 빈칸을 전부 채워라

수신한 메시지를 원장으로 검증할 때, 실사고 세 건이 가르쳐 준 규칙:

1. **어느 키로 조회하는가** — 조회 키는 줄머리 표식 하나뿐입니다. 본문에 사람이 손으로 쓴 유사 라벨을 키로 조회하면 "없음"이 나오고, 진짜 발신을 고스트로 판정할 뻔합니다. 처방은 규율이 아니라 **이름을 가르는 것**: 본문 라벨에는 아예 다른 단어를 쓰게 해서, 틀린 축으로 물을 가능성 자체를 없앱니다.
2. **언제 조회하는가** — 메시지 도착과 원장 기록은 동시가 아닙니다(약 25초 지연 관측). 조회 0건이면 **재조회 최소 1회**, 그래도 없으면 판정이 아니라 **질의**("폴백 쓰셨습니까?")로 올립니다. 거짓 고스트 판정의 비용(진짜 발신자 의심 = 승인 체계 마비)이 진짜 고스트를 늦게 잡는 비용보다 큽니다.
3. **어디까지 판정 가능한가** — 원장 시작 시각 이전 발신은 판정 불가입니다. "원장에 없으니 고스트"는 그 시각 이후에만 성립합니다.

같은 원리로: **에이전트 입력창의 자동 후속 제안(ghost text)을 오너 지시로 오인하지 마세요.** 지시뿐 아니라 승인도 출처 검증이 필요합니다.

## 3. 인박스 — 워커→master 상향 채널

워커는 master 페인 주소를 하드코딩하지 않고, 핀 파일(`~/.cmux_master_surface`)을 동적 참조해 push합니다(재시작 내성). 채널 실체는 append-only 파일 + 헤더 규약입니다.

### 감시는 3층 결정론

파일 채널은 폴링이라, master가 능동으로 읽을 때만 메시지를 봅니다. 17시간 방치 사고 후 확정한 3층:

1. **상주 Monitor** — `tail -F`로 인박스를 상시 감시, **헤더 전건 발화**. ⛔ 마커 어휘 필터(【완료】【경고】 같은 단어 목록) 금지 — 워커는 새 마커를 계속 발명하므로 폐쇄 목록은 반드시 뚫립니다(두 번 뚫린 실증). 소음 억제는 필터가 아니라 master의 배치 처리로 합니다.
2. **복원 스윕은 훅이 강제** — SessionStart 훅이 미처리 헤더 수·줄범위를 실측해 복원 컨텍스트에 자동 주입합니다. master의 기억과 무관하게 코드가 셉니다.
3. **스윕 기준은 "마지막 처리 줄번호 이후 전 구간"** — ⛔ `tail -N` 금지. 창 밖 도착분을 "미도착"으로 오보한 것이 사고의 원형입니다. "내가 못 봤다 ≠ 안 왔다." 순환 스냅샷마다 처리 완료 줄번호를 기록해 두고, 다음 복원은 그 줄 이후를 전부 훑습니다.

## 4. 워커 승인 요청 처리

워커의 도구 승인 요청(run command·update 등)은 master가 "가장 좋은 옵션"을 확인 후 자동 승인하되, 오너에게 보고합니다. 반복되는 stall(멈춤)은 사전 승인 정책을 정해 두고 자동 nudge합니다 — 단, **순간 스냅샷 1회로 hang을 판정하지 마세요**(지속 폴링 + 산출물 실측이 정본. 움직이는 대상을 한 장의 사진으로 판정하면 같은 아침에 두 번 틀립니다).
