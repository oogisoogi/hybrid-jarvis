# hybrid-jarvis

> **cmux(지휘) + cys(도구) 하이브리드로 Claude Code 에이전트 함대를 운영하는 「자비스」 구조의 실전 운영 자산 모음.**
> 반년 이상 매일 실운영하며 사고와 교훈으로 다듬은 문서·규율·스크립트·템플릿을 공유합니다.

## 이것은 무엇인가

한 사람(오너)이 여러 개의 Claude Code 세션을 동시에 부리려면 두 가지가 필요합니다.

1. **지휘 구조** — 어떤 세션이 명령권을 갖고, 어떤 세션이 일하며, 누가 감시하는가.
2. **생존 구조** — 재부팅·컨텍스트 만료·절전·사람의 부재에도 시스템이 맥락을 잃지 않는가.

이 레포는 그 두 가지를 **cmux**(멀티 페인 지휘 화면 + 원격 제어)와 **cys**(에이전트 함대 스폰·역할 관리 도구)의 하이브리드로 푼 실전 구조를 담고 있습니다. 핵심 설계 원칙 한 줄:

> **지휘는 cmux, 실행은 cys — 표시명은 사람 것, 주소는 기계 것.**

### 역할 위계

```
오너(사람)
  └─ master   — 단일 통제점. 오너와 항상 동행하는 "자비스". 상주 1기.
       ├─ CSO — 시스템 운영 감시자(센티널·자원·컨텍스트 감시). 상주 1기.
       └─ 워커 — 티켓 단위로 스폰·폐역되는 실행자. N기.
```

- **master는 직접 일하지 않는 것이 기본**입니다. 빠른 판단은 직접, 느린 작업은 워커에게 위임하고 철저히 감독합니다.
- 모든 워커의 완료·질문·충돌은 master에게 push되고, master만이 오너에게 보고합니다(단일 채널).

## 빠른 시작

1. `docs/01-architecture.md`를 읽고 자기 환경의 역할 배치를 정합니다.
2. `templates/CLAUDE.md.template`을 작업 루트의 `CLAUDE.md`로 복사해 자기 환경에 맞게 채웁니다.
3. `templates/`의 SESSION_STATE·RECOVERY·TODO 템플릿으로 작업기억 4층을 만듭니다.
4. `scripts/`에서 필요한 스크립트를 가져다 상단의 설정 변수를 자기 환경으로 바꿉니다.
5. master 세션을 띄우고 `docs/02-memory-recovery.md`의 복원 사이클을 한 번 돌려봅니다.

## 전제와 한계 (읽고 시작하세요)

- **cmux·cys는 이 레포의 산출물이 아닙니다.** 별도 개발자의 제품이며, 이 레포는 그 위에서의 *운영 방법*만 다룹니다. 두 도구가 없어도 문서의 원리(작업기억 4층·검증 규율·순환 규칙)는 tmux나 다른 멀티세션 환경에 이식 가능합니다.
- **도구는 빠르게 진화합니다.** 이 자산은 특정 시점의 실운영 스냅샷입니다. 명령어·옵션이 달라졌을 수 있으니, 문서의 *원리*를 취하고 세부는 자기 환경에서 실측하세요. 이 레포의 제1 규율이기도 합니다: **문서를 읽은 것은 실제 상태를 확인한 것이 아니다.**
- 스크립트는 개인정보 소거를 거친 사본입니다. 상단 설정 변수를 채우지 않으면 동작하지 않는 것이 정상입니다.

## 철학 요약 — 이 구조가 지키려는 것

1. **환각 0** — 출처·근거 없는 확신 금지. 모든 판정은 실측으로.
2. **규율보다 구조** — "다음부터 조심하자"는 네 번 실패한다. 자동 로드되는 문서와 래퍼가 기억을 대체해야 한다.
3. **미결에는 해소 판정법** — 열린 과제를 적을 때는 "무엇을 실행하면 해소를 아는가"를 함께 적는다.
4. **결함 이름 붙이기 전에 기대를 의심** — "우리 기대가 틀린 것"과 "대상이 고장난 것"을 먼저 가른다.
5. **아첨 금지** — 에이전트는 오너에게 언제나 비판적으로, 더 나은 안을 정리해 제안해야 한다.
