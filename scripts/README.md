# scripts/ — 실운영 스크립트 (개인정보 소거본)

> ⚠ 이 스크립트들은 실운영 사본에서 개인 경로·식별자를 소거한 것입니다.
> **상단의 설정 변수를 자기 환경으로 채우기 전에는 동작하지 않는 것이 정상입니다.**
> 도구(cmux·cys) 버전에 따라 명령·옵션이 다를 수 있으니, 가져다 쓰기 전에 자기 설치본에서 실측하세요.

## 통신 계층

| 파일 | 역할 |
|---|---|
| `master-send.sh` | **master 발신 단일 입구.** 입력줄 비움 확인→전송→도달 실측→Enter→제출 판정→append-only 원장 기록을 한 동작으로. 발신마다 1회용 표식(`[master#hex]`)을 자동 부착해 위조(고스트) 판별의 근거를 만든다. 본문은 인용 heredoc(`<<'EOF'`)으로만. |
| `inbox-push.sh` | 워커→master 상향 push. master 페인 주소를 하드코딩하지 않고 핀 파일을 동적 참조(재시작 내성). |
| `inbox-append.sh` | 인박스 파일 append 유틸(헤더 규약 부착). |

## 주소 해석 계층

| 파일 | 역할 |
|---|---|
| `jarvis-who.sh` | 역할→cmux 페인 해석. **cwd = 1차 키(권위)**, 탭 제목은 보조. 모호하면 첫 후보를 쓰지 않고 명시적 에러로 중단(엉뚱한 페인 send가 더 위험하므로). |
| `cys-who.sh` | 역할→cys 노드 해석(`role=` 필드 기반). |

## 워커 수명주기

| 파일 | 역할 |
|---|---|
| `spawn-worker.sh` | **워커 기동 단일 입구.** 모델 정본(`.claude/spawn-model`) 강제·역할 부여·페인 제목(번호+역할)·각성 주입까지 한 동작. 손 기동을 금지하는 이유는 docs/04 참조. |
| `master-complete-watch.sh` | 워커 완료 push 감시(완료워처). |

## 복원·감시 계층

| 파일 | 역할 |
|---|---|
| `master-surface-pin.py` | **SessionStart 훅.** /clear·재시작 직후 복원 지령을 컨텍스트에 자동 주입 + 미처리 인박스 헤더 수·줄범위를 결정론적으로 실측해 함께 주입. master 자기 페인 핀 파일 갱신도 담당. |
| `cso-system-sentinel.sh` | 경량 시스템 센티널(부하·프로세스 누적 감시 → 임계 시 지휘 세션을 깨움). "관측원은 부하와 정상관이어야 한다" 원칙의 구현. ⚠ 선택 의존: `cso-autoclear-safety-gate.sh`(이 레포 미포함)를 있으면 토큰 실측에 쓰고, **없으면 보수적 발화로 자동 폴백**한다(부재가 오류 아님). |
| `cmux-master-health.sh` | 정기 발화 전 건강 게이트(master 생존·채널 정상 확인). |

## 설치 순서 권장

1. `jarvis-who.sh`·`cys-who.sh` 먼저 — 주소 해석이 모든 것의 토대.
2. `master-send.sh` + 원장 경로 설정 — 통신 규율 확립.
3. `master-surface-pin.py`를 Claude Code SessionStart 훅에 등록 — 복원 자동화.
4. `spawn-worker.sh` — 워커 운영 개시.
5. 센티널·워처 — 무인 운영 단계에서.
